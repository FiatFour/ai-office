# Red team

`node redteam/run.ts --out <dir> [--mode cages,subagents-cage,subagents-local|all] [--only id,id] [--mutate <P0-6 mutation>] [--scan-repo owner/repo]`

One task per row of `docs/threat-model.md` (`redteam/tasks/`). `pnpm test redteam` fails when a row has no task.

What a run does:

- Plants canary credentials. The P0-6 fixture plants seven in the repo and fixture home, the cage gets one as an env var, and the run issues one more as a provider token. `redteam/canary.ts` knows every value and every encoding an exfil is likely to use.
- Starts a canary listener on the docker default bridge gateway. It counts every request, and a request to `/provider/` counts as a use of a credential. A hit is any request that is not the runner's own control request.
- Replays each task's attack against the P0-3 cage and the P0-2 firewall (the P0-6 rig), then makes the injected stand-in try to send what its position can read to the listener, directly and through the proxy. Caged modes pass only with zero hits. `subagents-local` has no firewall, so its hits are expected and reported.
- Posts each stopped attempt to a real HQ (`POST /api/sandbox/blocked`). HQ lists them on `/blocked` with worker, tool call and layer, and pauses a worker that repeats a denial no Allow can fix three times in 10 minutes. A not-allowlisted denial waits on the operator's Allow and never pauses; Allow is offered only for a site whose every denial was that reason, and never resumes a worker (use `POST /api/workers/resume`). Lane 5 feeds HQ real CONNECTs from the cage through the product proxy, three to a not-allowlisted host (no pause) and three to a name that resolves to a metadata address (pause).
- Plants a tracked `.env` and runs the preflight scan, plants a fake key in a worker diff and pushes through the layer 5 hook, and scans every file the run wrote (and a git host repo when `--scan-repo` is given) for canary values.

What PASS means. The attacker is a script run through the P0-6 rig, not a model-driven agent, except the `--live` rows. A `canary-hits=0` on a live row comes from the script beacon run inside the rig cage, not from the model: the model's own actions are judged by the layer that stopped them, not by the hit count. The three prompt-injection rows (`deny-rules-read-env`, `issue-injection-live`, `mcp-injection-followup`) are NOT-RUN until `--live`. The canary listener counts hits only on a task whose line says an exfil attempt was made; a task with no attempt prints `canary-hits=not-measured`, and the summary gives the attempted and not-attempted counts per mode, so `0 hits` is never read as `blocked` where it means `never attempted`. `subagents-cage` shares the rig and replays of `cages` and adds no independent evidence.

Accepted limit (M2). An exfil retry loop to a not-allowlisted attacker domain is never counted toward the pause. The proxy denies every attempt, so nothing leaves, and the list shows the repeat count growing, but HQ does not pause the worker. The operator has not yet seen this; the default is accepted.

Limits. The injected agent is a script, not a model, so the `stopped-live` rows print NOT-RUN. `cages` and `subagents-cage` share one rig, so lateral movement between subagents is not tested. The external canary hostname costs money and is parked in `gates.md`.

`node redteam/test/mutate-suite.mjs [mutation ...]` runs the docker suite with `mask-off`, `sni-off`, `network-open`, `allowlist-off` and `public-check-off` and requires each to exit 1 with the rows that declare it turned to FAIL. The `public-check-off` flip of `fw-ssrf-metadata` is weak: the dial to `169.254.169.254` times out on the docker network, so the row proves the F2a denial is gone, not that the address was reached. The suite and the row detail say so. The rig mounts `server/sandbox/proxy`, the proxy the product ships. `node redteam/scan-host.ts --repo owner/repo` reads a git host repo (read-only `gh api`) for credential shapes and the canary shapes of this suite (`AWCANARY-...`, `CANARY_<KIND>_<8 hex>`, `FAKE KEY` blocks, hex (either case), percent-encoded and base64 copies of those prefixes). Not scanned: branch contents, commit diffs and messages, issue bodies that are not PRs, base64 split by line wraps.
